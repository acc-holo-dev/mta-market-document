# DRM

## Честная формулировка

DRM **не** обещает «скрипт нельзя украсть». Покупатель владеет сервером; plaintext бывает в памяти. Продуктовая цель: массовое копирование дорого, лицензии контролируются, слив можно атрибутировать.

## Цель v2 (спецификация)

| Задача | Примитив |
|---|---|
| Подпись lease | Ed25519, ключ License Server |
| Шифр скрипта | AES-256-GCM, DEK |
| Обёртка DEK | от installation secret |
| Identity | keypair установки, не HWID |
| Срок работы офлайн | lease ~24ч, renew заранее |

Поток цели:

1. Продавец загружает ресурс → Build Tool собирает байткод и шифрует.
2. Покупатель активирует installation (ключ остаётся у него).
3. Модуль периодически обновляет подписанный lease.
4. Истёк lease и нет связи > 72ч → controlled stop, не «тихий вечный grace».

Шифруются Lua-скрипты. Модели движок читает открыто (ADR-005).

## Реализация сегодня

**Модуль:** `spike_drm_load` — hex payload, decrypt = `~byte`, `luaL_loadbuffer` в VM вызывающего ресурса. Это ответ на вопрос «можно ли встроиться в lifecycle», не протокол.

**Сайт (`routes/drm.ts`):**

- Активация по `licenseKey` = `License.id`.
- Проверка `purchase.buyerId === userId`.
- Ключи: `crypto.randomBytes(32).toString("hex")`.
- **Private key сохраняется в таблице Installation и отдаётся клиенту.**
- Verify сравнивает public+private+serial в БД.

Это v1-прототип. Несовместимо с ADR-003/007/008, пока модуль не начнёт проверять подпись lease и не перестанет слать секреты на сервер.

## Совместимость
